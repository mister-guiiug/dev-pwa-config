# Socle v7 — périmètre

_État au 04/10/2026. Socle courant : **6.23.0**, étiquette workflows `@v6`._

La v7 est une **majeure de rétrécissement** : retirer ce qui n'a pas d'adoptant,
sortir les données d'apps hors de la bibliothèque, et solidifier les types.
Elle ne porte pas de nouvelle pile (React / Vite / TS restent ceux de la 6.x).

## Fonctionnalités / chantiers

### 1. Retrait des modules expérimentaux (T12)

**Quoi.** Supprimer du paquet (exports, fichiers, tests, showroom) les
sous-chemins listés dans `experimental-modules.js` dont `retireAfter` est
dépassé, **sauf** ceux qui ont gagné un adoptant mesuré entre-temps.

**Date annoncée.** `2027-01-04` pour la vague posée le 04/10/2026.

**Règle.** CONTRIBUTING : un module reste s'il est dans le squelette **ou**
importé par ≥ 2 apps. Sinon, retrait à la majeure.

### 2. Engendrer les `.d.ts` (T13 / T15)

**Quoi.** Aujourd'hui ~156 exports sur 170 déclarent un `.d.ts` à la main.
La v7 doit :

- combler les exports sans `types` ;
- engendrer (ou vérifier) les `.d.ts` depuis les `.js` / JSDoc — un test
  refuse un export publié sans types, comme `npm run sync` refuse une copie
  divergente.

**Effet consommateur.** Meilleure complétion TS ; rupture seulement si un
type manuel était faux et que la génération corrige la surface.

### 3. Sortir catalogue et palettes de la bibliothèque

**Quoi.** `apps-catalog.js` et `themes.js` décrivent les apps, pas un besoin
partagé. Conséquences actuelles (STRATEGIE §2.2) :

- créer une app **exige une publication du socle** pour apparaître dans
  `FamilyApps` ;
- chaque app embarque le catalogue / les palettes des autres dans son bundle.

**Cible.** Fichier de données tiré hors paquet (ou écrit par le générateur /
une entrée d'app), bibliothèque sans données d'apps.

**Effet consommateur.** Rupture d'import : plus de
`@mister-guiiug/dev-pwa-config/apps-catalog` (ou équivalent) depuis le paquet ;
chemin de migration documenté dans `MIGRATIONS.md`.

### 4. Étiquette workflows `@v7`

**Quoi.** Comme à chaque majeure : `publish.yml` fait naître / avancer
l'étiquette mobile `v7` ; les apps migrent leurs `uses: …@v6` → `@v7`
(campagne `migrate-consumers` / Renovate).

**Effet consommateur.** PR par app (déjà industrialisé). GitHub **ne
redirige pas** les `uses:` — l'ordre publication → PR apps reste critique.

### 5. Hors v7 (restent ouverts, pas dans la majeure)

| Item | Pourquoi pas v7 |
| ---- | --------------- |
| F8 — écran « Nouveautés » (`version.json` + CHANGELOG) | besoin produit, pas rupture de paquet |
| OIDC Firebase / URLs Supabase | gestes propriétaire (GCP / console) |
| Squelette Tauri | seulement si un 3ᵉ projet Tauri naît |
| Montée React / Vite / TS | pas annoncée ; la 6.x porte déjà la pile cible |

## Prérequis avant d'ouvrir la majeure

1. **Corriger le registre expérimental** : `speech` (et tout chemin redevenu
   ≥ 2 apps) sort du registre dès maintenant, en 6.x — sinon la v7 casserait
   des apps légitimes.
2. **Rejouer le relevé d'adoption** juste avant le retrait (la date
   `retireAfter` n'est pas une obligation de retirer : c'est une porte).
3. **Écrire `MIGRATIONS.md` § v7** avec la liste finale des chemins retirés et
   le nouveau foyer du catalogue / des palettes.
4. **Changeset majeur** + preuve CI squelette (`starter-kit` construit sur
   le paquet) avant de faire avancer `v7`.

## Ce qui n'est PAS la v7

- Les bumps `actions/checkout@v7` / `setup-node@v7` (déjà en 6.x) — ce sont
  les majeures **GitHub Actions**, pas celle du paquet.
- Renommer le paquet (fait en 4.0.0).
- `pwa-env` / `pwa-doctor --fix` (livrés en 6.x, 04/10/2026).
